# Web application template

[![OpenSSF Scorecard](https://api.scorecard.dev/projects/github.com/orlavid/app-template-web/badge)](https://scorecard.dev/viewer/?uri=github.com/orlavid/app-template-web)

This repository is the start point for each web application that the build platform makes. Copy it to start a new application.

## Stack

- Vite, React and TypeScript in strict mode.
- Tailwind CSS 4 with shadcn/ui primitives.
- shadcn CLI version 4.23.0, with the `radix-nova` style. The project does not install the CLI as a package.
- `react-hook-form` and zod for forms.
- Vitest and Testing Library for unit tests.
- Playwright and axe for end-to-end tests.
- ESLint, Stylelint and Vale for checks.

## Requirements

- Node.js 22 or later.
- npm 10 or later.
- Vale 3. On macOS, run `brew install vale`.
- Docker, only to update the Linux screenshot baselines.

## Set up a new application

1. Copy this repository to a new folder.
2. Go to the new folder.
3. Run `python3 "$PLATFORM_ROOT/scripts/platform.py" start`.
4. Run `npm ci` to install the packages.
5. Run `npx playwright install chromium` to install the test browser.
6. Run `npm run check` to make sure that all checks pass.
7. Run `npm run dev` to start the development server.

## Folders

- `src/components/ui/`: shadcn/ui primitives. The shadcn CLI writes these files.
- `src/styles/vendor/shadcn-tailwind.css`: a copy of the shadcn CSS helpers from version 4.23.0. Do not edit this file.
- `src/components/<feature>/`: product components. The example is `contact-form/`.
- `src/styles/tokens.css`: the design tokens for the light theme and the dark theme.
- `e2e/`: Playwright tests and screenshot baselines.
- `specs/`: feature specs from Spec Kit.
- `docs/glossary.md`: the approved project terms.
- `.vale/styles/STE/`: the Simplified Technical English rules.

## Rules

`AGENTS.md` gives all the rules. The checks enforce these rules:

- ESLint stops a Radix import outside `src/components/ui/`.
- Stylelint stops a hex colour outside `src/styles/tokens.css`.
- Vitest stops the build when line coverage is less than 80%.
- Playwright stops the build when axe finds a violation.
- Playwright stops the build when a screenshot does not agree with its baseline.
- Vale stops the build when a Markdown file breaks an STE rule.

## Screenshot baselines

Each platform has its own baselines in `e2e/__screenshots__/<platform>/`. CI uses the Linux baselines.

CAUTION: Do not update the baselines to make a failed test pass. First, find the cause of the difference.

1. Run `npm run test:e2e:update` to update the baselines for your platform.
2. Start Docker.
3. Run `./scripts/update-linux-screenshots.sh` to update the Linux baselines.
4. Examine each changed image before you commit it.

## Writing rules

All Markdown files use Simplified Technical English. Vale checks the files in CI. The rules come from ASD-STE100, but this repository does not contain the ASD-STE100 dictionary.

To add a project term:

1. Add the term and its sense to `docs/glossary.md`.
2. Add the term to `.vale/styles/config/vocabularies/Project/accept.txt`.
3. Run `npm run docs:lint`.

## Supply chain

These controls protect the code, the dependencies and the release files:

- CI runs the type check, ESLint, Stylelint, Vitest, Vale, Playwright and `npm audit` on each pull request.
- CodeQL examines the TypeScript code and the workflow files on each pull request and each week.
- OpenSSF Scorecard examines the repository settings on each push to `main` and each week.
- Dependabot opens a pull request each week for npm packages, GitHub Actions, Docker images and the dev container.
- Each workflow pins each action to a full commit SHA. The SLSA generator must use a tag.
- Each Dockerfile and workflow pins each container image to a digest.
- Property tests use fast-check to give random input to the contact schema and to `cn`.

### Releases

When a maintainer pushes a `v*` tag, `release.yml` makes these files:

- `app-template-web-<tag>.tar.gz`: the contents of `dist/`.
- `app-template-web-<tag>.cdx.json`: the CycloneDX software bill of materials.
- `multiple.intoto.jsonl`: the SLSA build level 3 provenance for the two files above.
- `ghcr.io/orlavid/app-template-web:<version>`: the container image, with BuildKit provenance and an SBOM.

GitHub also keeps a signed build attestation for each file and for the image.

### Verify a release

1. Install `slsa-verifier` from the SLSA project.
2. Download the tarball and `multiple.intoto.jsonl` from the release page.
3. Run this command to verify the SLSA provenance:

```sh
slsa-verifier verify-artifact app-template-web-v1.0.0.tar.gz \
  --provenance-path multiple.intoto.jsonl \
  --source-uri github.com/orlavid/app-template-web \
  --source-tag v1.0.0
```

4. Run this command to verify the GitHub attestation of the tarball:

```sh
gh attestation verify app-template-web-v1.0.0.tar.gz --repo orlavid/app-template-web
```

5. Run this command to verify the GitHub attestation of the image:

```sh
gh attestation verify oci://ghcr.io/orlavid/app-template-web:1.0.0 --repo orlavid/app-template-web
```

Each command exits with code 0 when the file is correct. Do not use a file when a command fails.

### Run the container

The image runs nginx as a user that is not root. It listens on port 8080 and gives `/healthz` for health checks.

1. Run `docker build -t app-template-web .` to make the image.
2. Run `docker run --rm -p 8080:8080 app-template-web` to start the container.
3. Open `http://localhost:8080` in a browser.

## Known advisories

`npm audit` reports 0 vulnerabilities. CI runs `npm audit --audit-level=low` and stops on each finding.

The project does not install the `shadcn` package. That package gave 3 low findings in `deepmerge`, and no fixed version exists. To add a primitive, run the CLI at its pinned version:

1. Run `npx shadcn@4.23.0 add <name>`.
2. Run `npm audit` to make sure that the result is 0 vulnerabilities.

An override in `package.json` sets `minimatch` to version `11.0.5` or later. This override removes the `minimatch` advisory.
